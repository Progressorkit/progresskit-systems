Glikemia Premium

Dziennik glikemii na Androida z lokalną historią, wykresem, filtrami i raportem PDF. Podpisany APK 1.0 jest dostępny bezpośrednio; publikacja sklepowa i końcowe bramki jakości pozostają odrębne.

Dziennik glikemii Android
Odkryj projekt Glikemia Premium

Problem

Pomiary, kontekst posiłku i notatki potrzebują jednego uporządkowanego dziennika, który pozostaje dostępny na telefonie.

Rozwiązanie

Aplikacja .NET MAUI przechowuje pomiary na telefonie, porządkuje historię i tworzy raporty PDF. Nie wymaga własnego backendu danych zdrowotnych i nie zastępuje profesjonalnej porady medycznej.

Dla kogo

Osoby prowadzące własny dziennik glikemii

Potwierdzony zakres

  • Dodawanie, edycja i usuwanie pomiarów w lokalnej bazie SQLite, z walidacją wartości przed zapisem.
  • Kontekst pomiaru, WW/WBT i notatka są zapisywane razem z rekordem dziennika.
  • Historia ma stronicowanie po 50 rekordów, stabilną kolejność daty i ID oraz filtry dnia, tygodnia i miesiąca.
  • Wykres na ekranie historii przedstawia ostatnie pomiary z aktualnie załadowanego widoku.

Stan i dostęp

Istnieje APK 1.0. Lokalna kopia i źródłowy plik mają teraz identyczne 80 235 954 bajty i SHA-256; publikacji Play ani nowej instalacji nie zweryfikowano.

C# / .NET 10 / .NET MAUI / Android / SQLite / SkiaSharp / Microcharts.Maui / Plugin.LocalNotification

ProgressKit Mail

Wieloplatformowy klient pocztowy: Android, Linux i Windows oraz powiązany backend. Kod obejmuje IMAP/SMTP, MIME, foldery, szkice i ochronę danych; każda platforma ma własny zakres odbioru.

Poczta Android, Linux i Windows
Odkryj projekt ProgressKit Mail

Problem

Prywatna poczta wymaga czytelnego interfejsu oraz kontroli nad urządzeniami, danymi dostępowymi i odłączaniem konta.

Rozwiązanie

Android obsługuje rzeczywiste IMAP/SMTP, lokalny cache i powiadomienia FCM. Linux i Windows współdzielą silnik poczty, izolację kont i OAuth, a korzystają z natywnej ochrony systemowej. Backend zarządza dostępem urządzeń i trwałym stanem enrollmentu. Każda platforma ma osobny zakres odbioru i dystrybucji.

Dla kogo

Użytkownicy prywatnej, samodzielnie hostowanej poczty · Operatorzy kontrolujący dostęp urządzeń do skrzynek

Potwierdzony zakres

  • Android: odczyt IMAP, wysyłanie SMTP, zapis kopii Wysłanych i kontrolowane usuwanie wiadomości.
  • Android: lokalne widoki folderów, wyszukiwanie, szkice, oznaczenia odczytu i ulubionych oraz odkładanie wiadomości w Room.
  • Android: odczyt czytelnej treści MIME, tekstu i HTML, także przy części niepoprawnych metadanych wiadomości.
  • Android: tożsamość urządzenia i chroniony magazyn danych dostępowych wykorzystują mechanizmy Android Keystore.

Stan i dostęp

Lokalne APK/DEB/TAR.GZ/EXE/ZIP o różnych zakresach odbioru. Linux 1.0.0-10 i Windows instalatory nie są podpisanym publicznym wydaniem.

Kotlin / Jetpack Compose / Room / WorkManager / Android Keystore / Eclipse Angus Mail / Firebase Cloud Messaging / C# / .NET 10 / .NET / Avalonia 11.3.22 / WPF / MailKit 4.17.0 / MimeKit / PostgreSQL / Entity Framework Core / Secret Service / DPAPI / CNG / OAuth PKCE

ProgressKit Translator

Tłumacz wypowiedzi i tekstu PL–DE na Androida z rozpoznawaniem mowy, lokalnym przekładem, syntezą głosu i historią. Jakość całego przepływu audio wymaga dalszych prób fizycznych.

Tłumacz rozmów Android
Odkryj projekt ProgressKit Translator

Problem

Krótka rozmowa w dwóch językach wymaga połączenia rozpoznawania, tłumaczenia i odsłuchu w jeden kontrolowany cykl.

Rozwiązanie

Kotlin i Compose łączą sesję rozpoznawania mowy, tłumaczenia i syntezy z kontrolą stanu oraz wyborem dostępnych lokalnych modeli/głosów. Kod uwzględnia ograniczenia routingu Androida; wynik zależy od modeli i rzeczywistego urządzenia.

Dla kogo

Osoby prowadzące naprzemienne rozmowy po polsku i niemiecku

Potwierdzony zakres

  • Tłumaczenie tekstu i wypowiedzi w kierunkach niemiecki→polski oraz polski→niemiecki przez lokalne modele MLKit.
  • Sesja nasłuch→tłumaczenie→synteza→odtwarzanie ma jawne stany, tokeny generacji, anulowanie i ograniczone odzyskiwanie po błędach.
  • Lokalny ASR jest wybierany tylko dla zainstalowanego modelu potwierdzonego przez Android; brak modelu prowadzi do kontrolowanego fallbacku.
  • Gotowy lokalny głos TTS jest preferowany na podstawie języka i metadanych silnika.

Stan i dostęp

Lokalny podpisany Debug APK 0.2.2 został historycznie zaktualizowany na Redmi przez install -r; aktualny lokalny plik ma ten sam hash co raport. Publiczne wydanie UNKNOWN.

Vaeloria

Działający prototyp gry fantasy: eksploracja 3D, kolekcja istot, turowa walka, dziesięciu rywali AI, sześć strategii i lokalny turniej. Rozgrywka ma konkretne raporty desktopowe i fizycznego Androida.

Grywalny prototyp 3D
Odkryj projekt Vaeloria

Problem

Przygodowy świat, kolekcja stworzeń i walka potrzebują wspólnego postępu oraz oprawy, która mieści się w budżecie telefonu.

Rozwiązanie

Klient Godot integruje postać EOS, onboarding, kampanię Ziemi, las 3D, lokalne pojedynki i turnieje z jednym silnikiem domenowym. JSON zapisuje profil i oddzielną historię rywalizacji. Osobne API kont oraz czatu istnieje, ale nie realizuje multiplayerowej walki.

Dla kogo

Gracze zainteresowani eksploracją fantasy i taktycznymi pojedynkami · Uczestnicy prywatnych testów rozwijanej gry

Potwierdzony zakres

  • Kreator EOS z imieniem, fryzurą, kolorem włosów, strojem i aurą; onboarding, wybór starterów i samouczek prowadzą do rzeczywistej kampanii.
  • Eksploracja 3D: chód/bieg, kamera ze spring arm i kolizją, sterowanie klawiaturą, myszą i dotykiem; las zawiera ścieżki, mosty i interakcje.
  • Minimapa odkrywa sektory i znaczniki, zapisuje postęp oraz rozróżnia zebrane obiekty. Skrytki i diamenty aktualizują rzeczywistą kolekcję i zasoby po udanym zapisie.
  • Turowy Combat Engine rozstrzyga ataki, zdolności, MP, obrażenia, relacje żywiołów i statusy oraz odrzuca akcje niezgodne z aktywną turą.

Stan i dostęp

Udokumentowane lokalne i historycznie publiczne preview Android/Windows; APKdebug/Windows unsigned. Bez deklaracji sklepowego wydania ani finalnego odbioru platform.

Godot4.6.3.NET / C# / klient net9.0 / Domain/Application/Infrastructure net8.0 / GL Compatibility / Godot Shaders / MultiMesh / JSON saveV1 / ASP.NET Core / EFCore / PostgreSQL / SignalR / xUnit / GDScript harnessy QA / NSIS — Windows preview

ProgressKit Community / Lud&Pra

Platforma społecznościowa z publikacjami, rozmowami, społecznościami, wyszukiwaniem i obiegiem moderacji. Rozbudowana implementacja lokalna ma historyczne testy; publiczna beta pozostaje osobną bramką.

Platforma społecznościowa
Odkryj projekt ProgressKit Community / Lud&Pra

Problem

Dyskusje potrzebują czytelnych zasad, uzasadnionych decyzji moderacyjnych i możliwości odwołania, a uczestnicy chcą łatwo odnajdywać interesujące społeczności.

Rozwiązanie

Zapewnia wspólny mechanizm członkostwa, widoczności treści i dostępu do mediów oraz jawny lifecycle zgłoszenia moderacyjnego. Discovery pomaga przejść od tematu i fragmentu rzeczywistej rozmowy do społeczności, bez generowania fikcyjnej aktywności.

Dla kogo

Uczestnicy społeczności tematycznych · Twórcy i administratorzy społeczności · Moderatorzy

Potwierdzony zakres

  • Rejestracja, logowanie, wylogowanie i zarządzanie aktywnymi sesjami konta.
  • Weryfikacja adresu e-mail, ponowna wysyłka potwierdzenia oraz odzyskiwanie i reset hasła.
  • Tworzenie i zarządzanie społecznościami, lista własnych grup, widoczność Public/Private/Restricted, członkostwo oraz role administracyjne.
  • Polityki dołączania, wnioski o członkostwo z akceptacją/odmową oraz zaproszenia z akceptacją, odrzuceniem i anulowaniem.

Stan i dostęp

Zaimplementowany frontend WWW i backend; nowy target publicznej bety nie ma potwierdzonego wdrożenia. Lud&Pra i Progress Kit Community liczone jako jeden produkt.

ProgressKit Tax

Rozbudowany system biurowo-księgowy: kartoteki osób i firm, sprawy PL/DE/NL, dokumenty, workflow, księgi i ewidencje, raporty oraz portal Android. Wdrożenie produkcyjne i odbiór reguł księgowych są odrębne.

System biurowo-księgowy
Odkryj projekt ProgressKit Tax

Problem

Dane osób prywatnych, firm, dokumentów i rozliczeń międzynarodowych są rozproszone, a korekty księgowe muszą zachowywać spójną historię.

Rozwiązanie

Łączy kartoteki biura, przydzielanie pracy, weryfikację dokumentów i moduły księgowe w jednym modelu organizacji i uprawnień. Pozwala rozdzielić pracę osoby prowadzącej sprawę od niezależnego zatwierdzenia oraz udostępnić klientowi wyłącznie jawnie przyznany zakres spraw i dokumentów.

Dla kogo

Polskie biura rachunkowo-podatkowe · Klienci indywidualni ze sprawami PL/DE/NL · Przedsiębiorcy i reprezentanci spółek

Potwierdzony zakres

  • Rejestracja i logowanie, potwierdzanie konta, odzyskiwanie dostępu, kontrola sesji i wieloskładnikowego uwierzytelniania.
  • Model wielu biur z członkostwem i rolami Owner, Manager, Staff, Reviewer oraz Client; rozdzielone uprawnienia do osób i firm.
  • Kartoteki osób, JDG i spółek z adresami, identyfikatorami podatkowymi oraz powiązaniem firmy z osobą; wyszukiwanie i stronicowanie rejestrów.
  • Rejestr spraw PL/DE/NL z rokiem podatkowym, krajami, statusem i przypisanym pracownikiem. Ten obieg organizuje pracę nad sprawą; nie jest deklaracją automatycznego obliczania lub wysyłania zeznań.

Stan i dostęp

Lokalne buildy WWW/API i Debug APK. Publiczne wydanie aplikacji niepotwierdzone.

C# / .NET 10 / ASP.NET Core Identity / Entity Framework Core / PostgreSQL / Npgsql / Next.js / React / TypeScript / Kotlin / Jetpack Compose / Android Keystore / ClamAV / CSV / PDF

Adivara

Wielofirmowy backend dla organizacji opiekuńczych z członkostwem, rolami i kontrolowanym dostępem do podopiecznych. Zaimplementowana logika domenowa i API stanowią fundament produktu operacyjnego.

Backend wielu organizacji
Odkryj projekt Adivara

Problem

Firmy opiekuńcze potrzebują uporządkowania relacji między personelem, koordynatorami, podopiecznymi i rodziną przy zachowaniu odrębności danych organizacji.

Rozwiązanie

Oddziela konto użytkownika od jego członkostwa w organizacji i od uprawnień do konkretnego podopiecznego. Zmiana firmy, roli lub grantu jest sprawdzana na aktualnym stanie bazy, zamiast traktować samo zalogowanie jako prawo do wszystkich danych firmy.

Dla kogo

Firmy opiekuńcze · Koordynatorzy opieki · Opiekunowie i uprawnieni członkowie rodzin

Potwierdzony zakres

  • Logowanie przez ASP.NET Identity oraz kontrola sesji API z JWT.
  • Jedno konto może należeć do wielu organizacji; aktywne członkostwo określa kontekst pracy.
  • Rozdzielony model CompanyMembership z rolą i cyklem członkostwa oraz deklaratywne ograniczanie operacji do ról tenantowych.
  • Linkowanie i odpinanie profilu opiekuna od członkostwa przez kontrolowane endpointy API.

Stan i dostęp

Źródła backendu i dokumentacja; niepotwierdzona publiczna dystrybucja lub interfejs klienta.

C# / .NET 10 / ASP.NET Core / ASP.NET Identity / JWT / Entity Framework Core / PostgreSQL / Npgsql / xUnit / SQLite (testy) / Testcontainers (testy)

ProgressKit Vault Key

Demonstrator challenge-response Android–Linux z biometrią i podpisem kluczem AndroidKeyStore. Transport ADB służy wyłącznie programowaniu; projekt nie jest jeszcze gotowym magazynem danych ani systemem parowania.

Demonstrator klucza Android
Odkryj projekt ProgressKit Vault Key

Problem

Sprawdzenie możliwości zatwierdzania kryptograficznego wyzwania na telefonie przed projektowaniem właściwego procesu zaufanego parowania.

Rozwiązanie

Klient Python generuje losowe wyzwanie, przekazuje je przez ADB, a aplikacja Android prosi o silną biometrię i podpisuje je kluczem EC z Android Key Store. OpenSSL weryfikuje wynik; nie jest to gotowy magazyn ani system odblokowywania dokumentów.

Dla kogo

Wewnętrzne eksperymenty ProgressKit z uwierzytelnianiem urządzeń

Potwierdzony zakres

  • Kod generowania EC P-256 w Android Key Store z wymogiem silnej biometrii przy podpisie i unieważnianiem po zmianie zestawu biometrii.
  • Systemowy Biometric Prompt z Crypto Object; ścieżka przyjęcia wyzwania jest blokowana poza buildem DEBUG.
  • Klient Python generuje challenge 256-bit, pobiera publiczny wynik przez developerskie ADB/run-as i weryfikuje SHA256 with ECDSA za pomocą OpenSSL.
  • Przygotowane negatywne próby innego/zmienionego wyzwania i zmienionego podpisu oraz scenariusz anulowania; brak odnalezionego raportu ich fizycznego wykonania.

Stan i dostęp

Wyłącznie developerskie źródła i debug APK.

Kotlin / Android SDK36 / minSDK30 / AndroidKeyStore / androidx.biometric1.1.0 / EC P-256 / SHA256withECDSA / Python / OpenSSL / ADB — DEBUG ONLY

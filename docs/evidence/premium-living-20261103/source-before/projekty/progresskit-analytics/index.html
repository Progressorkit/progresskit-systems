Technologie

ProgressKit Analytics

Wewnętrzna analityka witryny, licznik ukończonych pobrań i moderowane opinie. Mały backend służy własnemu ekosystemowi ProgressKit i nie jest komercyjną platformą analityczną.

Od potrzeby do produktu

Dla kogo

  • Użytkownicy i odbiorcy ekosystemu ProgressKit

Problem

Rozwój portfolio wymaga informacji o wykorzystaniu strony bez dokładania zewnętrznego trackera i identyfikatorów urządzeń.

Dlaczego powstał

Rozwój portfolio wymaga informacji o wykorzystaniu strony bez dokładania zewnętrznego trackera i identyfikatorów urządzeń.

Rozwiązanie

Dostarcza podstawowe informacje o użyciu witryny i dystrybucji APK bez wprowadzania identyfikatora odwiedzającego. Oddziela zdarzenia strony od bazy produktu oraz od publicznie wyświetlanej kolejki zatwierdzonych opinii.

Architektura i technologie

  • Własny frontend wysyła ograniczone zdarzenia do backendu FastAPI i SQLite. Oddzielna część produktu obsługuje pobrania i opinie. Panel operatora jest narzędziem wewnętrznym.

Python / FastAPI / Pydantic / SQLite WAL / ASGI / JavaScript sendBeacon/fetch / Docker

Stan produktu i platform

Narzędzie wewnętrzne

Zakres funkcjonalny
Własna analityka
Dystrybucja
Kod i kontener do samodzielnego wdrożenia; nie potwierdzono bieżącego publicznego wydania i danych produkcyjnych.
Produkcja
Bieżący produkcyjny przepływ danych nie został odrębnie potwierdzony w audycie.

Backend HTTP

Implementacja
Collector, agregacje, download API i opinie są zaimplementowane.
Weryfikacja
Istnieją syntetyczne testy zapisu, walidacji, schematu,Range/prefetch, równoległego licznika, przerwanej wysyłki i moderacji; w tym audycie odczytano kod testów, bez uruchamiania realnej bazy.
Dystrybucja
Kod, Dockerfile i fragment konfiguracji serwera; aktualne publiczne połączenie frontend→baza niepotwierdzone.
Otwarte kwestie
Retencja, ochrona narzędzi operatora i rzeczywisty przepływ danych wymagają odbioru.

Panel WWW operatora

Implementacja
HTML/JS z agregatami i cyklicznym odświeżaniem.
Weryfikacja
Kod panelu potwierdzony; nie odczytywano aktualnych danych, kont, liczników ani opinii.
Dystrybucja
Przeznaczony do zaplecza.
Otwarte kwestie
Wyłącznie wewnętrzna warstwa; nie publiczny produkt SaaS.

Potwierdzony zakres

  • Zbieranie zdefiniowanych zdarzeń witryny: odsłon, kontaktów, otwarć projektu i przejść do zewnętrznych stron. [1]
  • Osobna baza SQLite przechowuje zdarzenia i umożliwia agregację według czasu i źródła kampanii. [1]
  • Własny frontend respektuje Do Not Track i ogranicza metadane zdarzeń; treść briefu i zapytań wyszukiwania nie jest dołączana do zdarzenia. [1]
  • Wewnętrzne podsumowania pokazują aktywność w wybranych oknach czasu i źródła kampanii. [1]
  • Wewnętrzny panel operatora odświeża agregaty zdarzeń i pobrań; wymaga osobnego zabezpieczenia i odbioru środowiska. [1]
  • Licznik pobrania aktualizuje się po ukończeniu odpowiedzi z plikiem; nie jest licznikiem unikalnych osób ani instalacji. [1]
  • Wznowienia pobierania i wstępne pobieranie nie są doliczane jako kolejne ukończone pobrania. [1]
  • Opinie obejmują ocenę, komentarz i wersję produktu. Publikowane są dopiero po decyzji operatora. [1]
  • Formularz opinii ma walidację danych i mechanizmy ograniczające powtórne zgłoszenia; wymaga dalszej oceny operacyjnej. [1]
  • Narzędzie operatora obsługuje kolejkę opinii i decyzje o ich publikacji lub usunięciu. [1]
  • Warstwa HTTP sprawdza przyjmowane dane i stosuje skonfigurowane nagłówki ochronne. [1]

Wyniki i granice weryfikacji

  • Zaimplementowano zbieranie zdarzeń, semantykę ukończonego pobrania i kolejkę opinii przed publikacją.
  • Nie przedstawiono licznika jako liczby instalacji ani zweryfikowanych użytkowników.

ProgressKit Reel Agent

Wewnętrzne narzędzie do pionowych filmów: lokalny panel, planowanie scen, synteza głosu, napisy i render FFmpeg. Rzeczywisty lokalny E2E jest udokumentowany; użyty głos ma nierozstrzygnięte prawa komercyjne.

Od potrzeby do produktu

Dla kogo

  • Wewnętrzna produkcja materiałów ProgressKit
  • Operator lokalnego pipeline wideo

Problem

Przygotowanie krótkiego filmu z własnych materiałów wymaga powtarzalnego łączenia scenariusza, lektora, napisów i eksportu.

Dlaczego powstał

Połączyć lokalne generowanie treści i powtarzalne składanie krótkich filmów w jednym narzędziu.

Rozwiązanie

Panel Fast API zapisuje zadania w SQLite i uruchamia jednego pracownika. Lokalna Ollama wybiera zatwierdzone frazy i plan scen, Piper tworzy WAV, a FFmpeg renderuje film z kontrolą metadanych i próbek scen. Narzędzie nie publikuje automatycznie materiałów.

Architektura i technologie

  • Jednoużytkownikowy lokalny panel Fast API/Jinja 2, SQLite WAL, pojedynczy worker i izolowane katalogi zadań. Planista używa lokalnego API Ollama, lektor lokalnego Piper, renderer i walidator oddzielnych procesów FFmpeg/FFprobe. Brak chmurowej publikacji, kont i systemu wielodostępnego.

Python 3.12 / FastAPI / Pydantic / Jinja2 / SQLite WAL / Ollama / Qwen3 / Piper ONNX / FFmpeg / FFprobe

Potwierdzony zakres

  • Lokalny panel i REST: tworzenie zadań, historia, etapy, logi, anulowanie, retry oraz podgląd i pobieranie ukończonego eksportu. [1]
  • Trwała kolejka SQLite WAL z historią zdarzeń i przywracaniem stanu po restarcie; retry tworzy nową kopię zadania. [1]
  • Import własnych obrazów i filmów oraz opcjonalnego podkładu; walidacja typów, rozmiarów, ścieżek i metadanych mediów. [1]
  • Planowanie przez lokalny model Ollama z walidacją dozwolonych faktów, mediów i czasu. Ograniczony planista Qwen3 wybiera gotowe zatwierdzone frazy; fallback do szablonu jest jawnie oznaczony. [1]
  • Polski lektor Piper z lokalnego modelu ONNX, zapis pochodzenia/licencji głosu i pomiar rzeczywistych okien audio; użyty głos ma nierozstrzygnięte prawa komercyjne. [1]
  • Renderer H.264/AAC z profilami preview/final, formatem 9:16, przejściami, napisami UTF-8 i opcjonalnym ściszaniem muzyki pod narracją. [1]
  • Kontrola FFprobe parametrów eksportu oraz dekodowanie próbki z każdej sceny; końcowy MP4 jest udostępniany po walidacji. [1]
  • Raport zadania rozdziela pochodzenie scenariusza, status głosu, fallback, wynik FFmpeg i walidację; wywołania narzędzi używają list argumentów. [1]

Wyniki i granice weryfikacji

  • Raport 01.11.2026: pełne zadanie 192,371 s; inferencja Qwen3 122,675 s, status validated bez fallbacku; Piper wygenerował trzy polskie wypowiedzi; FFmpeg kod 0.
  • Gotowy artefakt 15,000 s,1080×1920,30FPS,450 klatek,H.264/AAC. SHA-256 i parametry odczytano ponownie 02.11.2026 bez publikowania filmu.
  • Scenariusz opiera się na wąskiej liście zatwierdzonych twierdzeń, a nie na swobodnym dopisywaniu funkcji produktu.

Wyzwania i rozwiązania

Porównano raport planowania, syntezy, FFmpeg i walidacji ukończonego zadania.
Przyczyna
Poprawny plik MP4 sam nie dowodzi wykonanej inferencji ani praw do głosu.

Wynik

  • Ustalić prawa do komercyjnej publikacji modelu głosu/wynikowych nagrań albo zastąpić głos jednoznacznie dopuszczonym.

ProgressKit Vault Key

Demonstrator challenge-response Android–Linux z biometrią i podpisem kluczem AndroidKeyStore. Transport ADB służy wyłącznie programowaniu; projekt nie jest jeszcze gotowym magazynem danych ani systemem parowania.

Od potrzeby do produktu

Dla kogo

  • Wewnętrzne eksperymenty ProgressKit z uwierzytelnianiem urządzeń

Problem

Sprawdzenie możliwości zatwierdzania kryptograficznego wyzwania na telefonie przed projektowaniem właściwego procesu zaufanego parowania.

Dlaczego powstał

Sprawdzić wykorzystanie klucza Android i jawnej zgody biometrycznej do podpisywania wyzwań.

Rozwiązanie

Klient Python generuje losowe wyzwanie, przekazuje je przez ADB, a aplikacja Android prosi o silną biometrię i podpisuje je kluczem EC z Android Key Store. OpenSSL weryfikuje wynik; nie jest to gotowy magazyn ani system odblokowywania dokumentów.

Architektura i technologie

  • Android Kotlin / Android Key Store / androidx.biometric oraz Linux Python / OpenSSL. ADB i run-as służą demonstracji w debug APK. Brak zaufanej rejestracji/przypięcia klucza telefonu, transportu Bluetooth i kompletnego Vault.

Kotlin / Android SDK36 / minSDK30 / AndroidKeyStore / androidx.biometric1.1.0 / EC P-256 / SHA256withECDSA / Python / OpenSSL / ADB — DEBUG ONLY

Potwierdzony zakres

  • Kod generowania EC P-256 w Android Key Store z wymogiem silnej biometrii przy podpisie i unieważnianiem po zmianie zestawu biometrii. [1]
  • Systemowy Biometric Prompt z Crypto Object; ścieżka przyjęcia wyzwania jest blokowana poza buildem DEBUG. [1]
  • Klient Python generuje challenge 256-bit, pobiera publiczny wynik przez developerskie ADB/run-as i weryfikuje SHA256 with ECDSA za pomocą OpenSSL. [1]
  • Przygotowane negatywne próby innego/zmienionego wyzwania i zmienionego podpisu oraz scenariusz anulowania; brak odnalezionego raportu ich fizycznego wykonania. [1]

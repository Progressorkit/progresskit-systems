Zaplecze ProgressKit

Narzędzia przygotowania publicznych wydań, lokalnego podglądu oraz konfiguracje współpracy witryny z backendem. Dokumentacja oddziela kontrolę artefaktów od potwierdzonego działania serwera.

Od potrzeby do produktu

Dla kogo

  • Użytkownicy i odbiorcy ekosystemu ProgressKit

Problem

Aplikacje, API i dystrybucja plików muszą współpracować, zachowując dane i możliwość wycofania zmiany.

Dlaczego powstał

Aplikacje, API i dystrybucja plików muszą współpracować, zachowując dane i możliwość wycofania zmiany.

Rozwiązanie

Rozdziela publikowaną stronę, proces API, plik dystrybucji i trwałe dane. Przygotowanie wydania wiąże manifest i hashe ze źródłami, a procedura wycofania kodu zachowuje nowsze dane zamiast nadpisywać je starym backupem.

Architektura i technologie

  • Statyczne pliki publiczne + osobny kontener API + reverse proxy + trwałe dane poza wydaniem. Repozytorium zawiera fragmenty Compose/Caddy i narzędzia pakowania, lecz nie kompletny, zweryfikowany stan infrastruktury produkcyjnej.

Docker / Caddy / Linux / Python / FastAPI / SQLite / GitHub Actions / GitHub Pages / SHA-256 / deterministyczne archiwa

Stan produktu i platform

Infrastruktura

Zakres funkcjonalny
Zaplecze wydania i usług
Dystrybucja
Artefakty statyczne i konfiguracje do wdrożenia; zaplecze nie jest osobnym produktem komercyjnym.
Produkcja
Konfiguracje i narzędzia istnieją. Nie wykonywano nowego odbioru serwera, backupu ani odtwarzania produkcji.

Narzędzia lokalnego wydania

Implementacja
Allowlist, staging, manifest i paczkowanie są zaimplementowane; lokalny preview wykorzystuje te same jawne ścieżki.
Weryfikacja
Odczytano kod oraz zachowane lokalne raporty. Niczego nie uruchamiano i nie publikowano podczas audytu.
Dystrybucja
Źródła narzędzi i przygotowywalny publiczny artefakt.
Otwarte kwestie
Kandydat po nowych zmianach wymaga własnego manifestu i ponownej walidacji; stary hash nie opisuje bieżącego dirty tree.

Środowisko serwerowe

Implementacja
Konfiguracje przykładowe i runbooki są dostępne.
Weryfikacja
NOT_VERIFIED_CURRENT_REMOTE: brak SSH, odczytu realnych mountów, logów lub baz w tym audycie.
Dystrybucja
To infrastruktura usług, nie aplikacja instalowana przez odbiorcę.
Otwarte kwestie
Konfiguracja backupu nie jest dowodem wykonanego backupu lub odtworzenia; pełny aktualny HTTPS, monitoring irollback wymagają odrębnego dowodu operatora.

Potwierdzony zakres

  • Konfiguracje kontenera backendu i trwałych danych oddzielają proces aplikacji od publicznego wydania strony. [1]
  • Fragmenty konfiguracji reverse proxy rozdzielają publiczną witrynę, API i materiały wewnętrzne. [1]
  • Przygotowano reguły nagłówków i logowania dla dystrybucji produktu; obecność konfiguracji nie dowodzi jej aktywacji na serwerze. [1]
  • Lokalny podgląd korzysta z tej samej jawnej listy publicznych plików co wydanie. [1]
  • Deterministyczna paczka ma manifest plików i SHA-256 oraz zapisuje tożsamość źródeł i stan lokalnych zmian. [1]
  • Proces CI sprawdza generowanie i testy; publikacja wymaga osobnego odbioru właściciela. [1]
  • Procedura backupu i odtwarzania rozdziela odzyskanie danych od wycofania kodu i konfiguracji. [1]
  • Procedura wydania obejmuje sprawdzenie środowiska, zachowanie poprzedniego wydania i weryfikację artefaktów. [1]

Wyniki i granice weryfikacji

  • Narzędzia oddzielają publiczny artefakt od źródeł, dokumentacji i danych.
  • Zapis tożsamości źródeł uwzględnia lokalne zmiany robocze; sam HEAD nie jest hashem całego wydania.

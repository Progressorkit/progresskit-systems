SaaS

Adivara

Wielofirmowy backend dla organizacji opiekuńczych z członkostwem, rolami i kontrolowanym dostępem do podopiecznych. Zaimplementowana logika domenowa i API stanowią fundament produktu operacyjnego.

Backend wielu organizacjiŹródła: 2026-11-02
ProblemArchitekturaFunkcjePlatformyDowodyGaleriaWyzwaniaRozwójDostęp

Od potrzeby do produktu

Dla kogo

  • Firmy opiekuńcze
  • Koordynatorzy opieki
  • Opiekunowie i uprawnieni członkowie rodzin

Problem

Firmy opiekuńcze potrzebują uporządkowania relacji między personelem, koordynatorami, podopiecznymi i rodziną przy zachowaniu odrębności danych organizacji.

Dlaczego powstał

Zbudować wspólną podstawę organizacyjną i uprawnienia przed rozwijaniem pełnych procesów operacyjnych.

Rozwiązanie

Oddziela konto użytkownika od jego członkostwa w organizacji i od uprawnień do konkretnego podopiecznego. Zmiana firmy, roli lub grantu jest sprawdzana na aktualnym stanie bazy, zamiast traktować samo zalogowanie jako prawo do wszystkich danych firmy.

Architektura i technologie

  • Warstwy Domain, Application, Infrastructure i API na .NET 10; EF Core/PostgreSQL, ASP.NET Identity oraz JWT. Centralny scope zasobów podopiecznego uzupełnia granicę tenantową. Część testów używa SQLite, a migracje i API mają scenariusze PostgreSQL/Testcontainers.

C# / .NET 10 / ASP.NET Core / ASP.NET Identity / JWT / Entity Framework Core / PostgreSQL / Npgsql / xUnit / SQLite (testy) / Testcontainers (testy)

Potwierdzony zakres

  • Logowanie przez ASP.NET Identity oraz kontrola sesji API z JWT. [1]
  • Jedno konto może należeć do wielu organizacji; aktywne członkostwo określa kontekst pracy. [1]
  • Rozdzielony model CompanyMembership z rolą i cyklem członkostwa oraz deklaratywne ograniczanie operacji do ról tenantowych. [1]
  • Linkowanie i odpinanie profilu opiekuna od członkostwa przez kontrolowane endpointy API. [1]
  • Jawne przyznawanie i cofanie rodzinie dostępu do konkretnego podopiecznego; operacje są częścią istniejącego API. [1]
  • Centralny zakres dostępu do podopiecznego łączy organizację, rolę i jawnie przyznane uprawnienia rodziny. [1]
  • Warstwa dostępu do danych egzekwuje granice organizacji oraz uprawnienia do zasobu. [1]
  • Modele domenowe pacjentów, opiekunów i przypisań obejmują stan oraz zakres dat; okresy stawek mają walidację kwoty, waluty i dat. To fundament domeny, a nie pełny moduł payroll lub produkcyjny Patient CRUD. [1]
  • Lokalny moduł przekazywania kontaktu zmiennika obejmuje modele zgody i reguły dostępu. Nie został jeszcze włączony do operacyjnego API. [1]

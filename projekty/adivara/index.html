SaaS

Adivara

Fundament wielofirmowego systemu dla branży opiekuńczej, skupiony na organizacjach, rolach i kontrolowanym dostępie do podopiecznych.

PrototypŹródła: 2026-08-27
ProblemArchitekturaFunkcjeGaleriaWyzwaniaRozwójDostęp

Od potrzeby do produktu

Dla kogo

  • Firmy opiekuńcze
  • Koordynatorzy opieki
  • Opiekunowie i uprawnieni członkowie rodzin

Problem

Firmy opiekuńcze potrzebują uporządkowania relacji między personelem, koordynatorami, podopiecznymi i rodziną przy zachowaniu odrębności danych organizacji.

Dlaczego powstał

Zbudować wspólną podstawę organizacyjną i uprawnienia przed rozwijaniem pełnych procesów operacyjnych.

Rozwiązanie

Backend rozdziela organizacje i role, wiąże konta z personelem oraz udostępnia centralny model nadawania i odwoływania dostępu członkom rodzin.

Architektura i technologie

  • Warstwy Domain, Application, Infrastructure i API w .NET.
  • ASP.NET Core Identity, role organizacji oraz centralny zakres dostępu do danych.
  • Entity Framework Core i PostgreSQL utrwalają organizacje, członkostwa oraz historię udzielonego dostępu.

C# / .NET / ASP.NET Core / Entity Framework Core / PostgreSQL / ASP.NET Core Identity / JWT / xUnit

Potwierdzony zakres

  • Logowanie i tożsamość użytkowników
  • Wybór organizacji i role członkostwa
  • Izolacja danych organizacji w warstwie aplikacji i modelu bazy
  • Powiązanie członkostwa z profilem opiekuna
  • Nadawanie i odwoływanie dostępu członka rodziny do podopiecznego
  • Centralny zakres autoryzowanych odczytów danych podopiecznych

Wyniki i granice weryfikacji

  • Raport poprawki z sierpnia 2026 zapisuje 203 testy zakończone PASS: 91 API, 67 domenowych i 45 infrastrukturalnych; testów nie uruchamiano ponownie w audycie portfolio.
  • Potwierdzone obszary obejmują izolację organizacji i cykl nadawania oraz odwoływania dostępu na danych testowych.
  • Raport poprawki nie zamyka całościowego odbioru bezpieczeństwa ani produkcji.

Materiały z produktu

Galeria zostanie uzupełniona po przeglądzie materiałów z produktu. Obecna prezentacja opiera się na opisanych źródłach.

Wyzwania i rozwiązania

Wyzwanie
Rosnący zestaw operacji na danych podopiecznych potrzebował jednolitego sposobu egzekwowania uprawnień.
Analiza
Przegląd architektury i testy dostępu wskazały potrzebę wspólnego mechanizmu dla list oraz pojedynczych zasobów.
Przyczyna
Rozproszone sprawdzanie uprawnień zwiększało zależność poprawności od każdej implementowanej operacji.
Decyzja i poprawka
Wprowadzono centralny zakres autoryzowanych zapytań i deklaratywną politykę dla zasobów, powiązane z aktualnym stanem członkostwa.
Weryfikacja
Historyczny raport dokumentuje testy poprawnych uprawnień, cofnięcia dostępu i izolacji organizacji; pełny zapisany zestaw liczy 203 PASS.
Wynik
Lokalnie zweryfikowano wspólną granicę dostępu. Pełny odbiór bezpieczeństwa i gotowość produkcyjna pozostają otwarte.

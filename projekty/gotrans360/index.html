GoTrans360

Zaplecze MVP transportowego: interfejs dyspozytora i pasażera, API przewozów oraz eksperymentalne dopasowanie tras. Dane demonstracyjne i niepołączone przepływy wymagają dalszej integracji.

ProblemArchitekturaFunkcjePlatformyDowodyGaleriaWyzwaniaRozwójDostęp

Od potrzeby do produktu

Dla kogo

  • Przewoźnicy
  • Dyspozytorzy
  • Docelowo pasażerowie i nadawcy przesyłek

Problem

Ręczne planowanie przewozów i rozproszone dane o trasach, pojazdach i zapotrzebowaniu utrudniają wykorzystanie dostępnych miejsc i ograniczanie pustych przebiegów.

Dlaczego powstał

Sprawdzić wspólny model tras i floty oraz dopasowanie zapotrzebowania do przejazdów przed uruchomieniem pełnej usługi przewozowej.

Rozwiązanie

Monorepo rozdziela dwa interfejsy Next.js, API Node.js, modele Prisma i moduł dopasowania. To fundament produktu transportowego, z jawnymi granicami między działającym kodem a demonstracyjnymi ekranami.

Architektura i technologie

  • Dwa interfejsy Next.js: dyspozytor i pasażer.
  • API Node.js i Prisma; frontend nie korzysta jeszcze z całości API.
  • Osobny moduł heurystyk i adapter Valhalla.

Next.js / React / TypeScript / Node.js / Prisma / PostgreSQL / PostGIS / pnpm / Turborepo

Potwierdzony zakres

  • Interfejs dyspozytora z ekranami floty, tras i dopasowania; dane operacyjne tych widoków są demonstracyjne. [1]

  • Sesja cookie i role w aplikacji dyspozytora oraz weryfikacja tokenu w osobnym API. [1]
  • Endpointy przejazdów, pojazdów i przewoźników oraz modele Prisma; integracja z frontendami pozostaje otwarta. [1]
  • Heurystyka dopasowania według miejsc, odległości objazdu i szacowanego zysku, oparta o Haversine. [1]
  • Adapter zapytań trasowania do Valhalla, przygotowany jako kod integracyjny. [1]

Do potwierdzenia lub ukończenia

  • Połączyć wyszukiwanie, rezerwację i panel z autoryzowanym backendem.

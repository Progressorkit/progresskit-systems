Technologie

ProgressKit Remote

Wewnętrzna integracja zdalnej pomocy oparta na Aspia: pakiety próbne, infrastruktura Router/Relay i przygotowanie ograniczonego Hosta. Pełna sesja Windows–Linux pozostaje nieodebrana.

Integracja pomocy zdalnejŹródła: 2026-11-02
ProblemArchitekturaFunkcjePlatformyDowodyGaleriaWyzwaniaRozwójDostęp

Od potrzeby do produktu

Dla kogo

  • Wewnętrzny operator pomocy technicznej ProgressKit

Problem

Zdalna pomoc wymaga powtarzalnego pakowania natywnego klienta i Hosta oraz jawnego odbioru lokalnej zgody, uprawnień i rozłączenia.

Dlaczego powstał

Zbudować kontrolowaną integrację istniejącego silnika zdalnego pulpitu dla pomocy technicznej.

Rozwiązanie

Projekt integruje upstream Aspia i własne skrypty pakowania, kontroli integralności i publicznego profilu połączenia. Rozwijana poprawka źródłowa ogranicza kanały i import ustawień; testy przenośnej polityki nie zastępują kompilacji Windows ani sesji fizycznej.

Architektura i technologie

  • Aspia 3.1.2 dostarcza silnik i role klienta, Hosta, Routera oraz Relaya. ProgressKit rozwija integrację, pakowanie i ograniczony profil Hosta. Przygotowane źródła Windows wymagają osobnej kompilacji i odbioru.

Aspia 3.1.2 / GPL-3.0-or-later / C++17 / Qt / SQLite / NSIS / Node.js / Bash / PowerShell — przygotowana ścieżka build

Potwierdzony zakres

  • Próbne pakiety Linux i Windows integrują natywnego klienta oraz Hosta Aspia, z kontrolą pochodzenia i integralności. [1]
  • Generator profilu połączenia przyjmuje wyłącznie publiczne ustawienia; nie umieszcza danych dostępowych operatora w pakiecie. [1]
  • Przygotowane procedury Routera i Relaya mają historyczny raport stanu usług. Działający proces nie potwierdza sesji pulpitu. [1]
  • Przygotowana poprawka źródłowa Hosta ogranicza zakres zdalnej sesji i wymaga osobnej kompilacji oraz odbioru Windows. [1]
  • Źródłowy importer ustawień kontroluje spójność profilu; zachowanie docelowego instalatora nie zostało odebrane. [1]
  • Przygotowana ścieżka budowy ma weryfikować zgodność Hosta i instalatora. Zabezpieczony pakiet nie został jeszcze zbudowany. [1]
  • Lokalne testy diagnostyczne wykorzystują dane syntetyczne. Poprawne logowanie operatora i pełna sesja pozostają niepotwierdzone. [1]

Weryfikacja
Historycznie wykonano testy samodzielnej polityki; pełny Host Windows i fizyczna sesja pozostają NOT RUN.
Wynik
Potwierdzono pracę integracyjną opartą na Aspia, bez deklaracji autorskiego silnika lub gotowego dostępu zdalnego.

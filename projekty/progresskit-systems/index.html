Technologie

ProgressKit Systems

Katalog produktów i realizacji z pełnymi prezentacjami, wyszukiwaniem i showroomem Three.js. Wspólny model danych zasila karty, podstrony i technologie, a aktualne zmiany wizualne wymagają odbioru.

Od potrzeby do produktu

Dla kogo

  • Użytkownicy i odbiorcy ekosystemu ProgressKit

Problem

Produkty zmieniają się szybciej niż ręcznie utrzymywane prezentacje. Opisy i statusy wymagają jednego punktu aktualizacji.

Dlaczego powstał

Produkty zmieniają się szybciej niż ręcznie utrzymywane prezentacje. Opisy i statusy wymagają jednego punktu aktualizacji.

Rozwiązanie

Oddziela źródłowe informacje o produktach od szablonów prezentacji. Ten sam katalog zasila case studies, technologie, filtrowanie i showroom; przeglądanie pozostaje dostępne w HTML, a rozbudowane 3D jest dodatkową warstwą obsługi i oprawy.

Architektura i technologie

  • Generator Python i katalog JSON → statyczne HTML/CSS/Java Script; lokalnie dostarczane moduły Three.js dla showroomu i niewielkiej sceny Usług; CSS3D/Canvas dla Procesu; Fast API jest oddzielnym backendem analityki i dystrybucji produktu, nie serwerem katalogowym.

Python / HTML / CSS / JavaScript ES modules / Three.js / WebGL2 / Canvas2D / CSS3D / JSON / GitHub Actions / FastAPI (osobne API)

WWW desktop

Implementacja
Działający katalog i statyczne case studies oraz interaktywny showroom 3D.
Weryfikacja
Odczytano lokalne raporty funkcjonalne, lifecycle i capture. Podczas tego audytu nie uruchamiano kolejnych przeglądarek ani pomiarów.
Dystrybucja
Lokalny kandydat i allowlistowane artefakty.
Otwarte kwestie

WWW mobile

Implementacja
Responsywny układ, dotyk, jeden aktywny kryształ showroomu, uproszczona scena Usług i pionowy Proces.
Weryfikacja
Raporty obejmują emulację viewportu 390×844 i dotyku; brak nowego dowodu fizycznego telefonu dla aktualnego passu.
Dystrybucja
Ten sam statyczny frontend.
Otwarte kwestie
Emulacja nie jest testem wydajności na rzeczywistym telefonie; część ujęć pokazuje tylko obszar widocznego viewportu.

Potwierdzony zakres

  • Walidowany katalog JSON przechowuje tożsamości, opisy, funkcje, status, dostępność, źródła i analizy realizacji zamiast ręcznie powielanych kart. [1]
  • Generator Python tworzy indeks katalogu i osobne adresy case studies z problemem, rozwiązaniem, architekturą, funkcjami, galerią i dalszym rozwojem. [1]
  • Wyszukiwanie, kategorie, technologie i etap produktu mają stan w URL, obsługę powrotu historii i bezpośredni wybór projektu. [1]
  • Treść stron jest prerenderowana. Filtry wymagają Java Script, ale lista projektów i pełne podstrony pozostają dostępne jako statyczny HTML. [1]
  • Katalog technologii prowadzi do przefiltrowanych realizacji, a sitemap i metadane generowane są z tych samych rekordów. [1]
  • Showroom jest rzeczywistą sceną Three.js/Web GL2: kamera perspektywiczna, geometria kapsuły i kryształów, materiał transmisyjny, energia i światła. [1]
  • Raycasting wskazuje rzeczywistą geometrię obiektu; wybór projektu przekazuje sterowanie istniejącej warstwie treści, routingu i zdarzeń. [1]
  • Klawiatura, focus, Escape, reduced motion i statyczny fallback zachowują dostęp do projektów. Renderowanie usypia poza viewportem i podczas odczytu rozwiniętej treści. [1]
  • Osobny, niewielki renderer Usług pokazuje dwa szklane obiekty; interakcja zmienia światło i delikatny rozkład materiału, a treści i CTA pozostają semantycznym HTML. [1]
  • Proces pracy jest ciągiem sześciu komór CSS3D z lekkim Canvas energii, który czyta istniejący stan etapów i nie przejmuje sterowania scrollem. [1]
  • Wspólny lifecycle uwzględnia zmianę widoczności, rozmiaru i DPR, utratę kontekstu Web GL oraz jawne zwalnianie zasobów przy opuszczeniu strony. [1]
  • Galeria używa lokalnych materiałów z opisami, klawiaturą i przywracaniem fokusu; linki obrazów pozostają dostępne poza modalem. [1]
  • Brief projektu tworzy lokalny plik tekstowy i korzysta z drukowania przeglądarki; kontakt e-mail jest jawną akcją użytkownika, bez automatycznej wysyłki formularza. [1]
  • Walidacja odrzuca niebezpieczne ścieżki galerii, niesprawdzone adresy zewnętrzne oraz prywatne lokalizacje lub ciągi przypominające sekrety w publicznym rekordzie. [1]
  • Publiczny pakiet powstaje z jawnego allowlistu; prywatna dokumentacja, dane i katalog źródłowy nie są publikowane razem z repozytorium. [1]

Wyniki i granice weryfikacji

  • Wspólny model zasila katalog, technologie i podstrony bez wymagania backendu katalogowego.
  • Nowszy lokalny proof Services/Process zawiera 99 regresji (55Node i 44Python),27 kontroli lifecycle oraz 17 kontroli capture; są to oddzielne zestawy, nie jeden reporter.
  • Baza FPS jest historyczna: zachowany raport Core podaje 58,946FPS; późniejsza regresja 45,111FPS, a izolacja A/B43,401FPS z warstwą Services i 41,465FPS bez niej. Nie udowodniono prostego związku przyczynowego ani aktualnych 60FPS.

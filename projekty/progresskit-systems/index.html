Problem

Dlaczego powstał

Produkty zmieniają się szybciej niż ręcznie utrzymywane prezentacje. Opisy i statusy wymagają jednego punktu aktualizacji.

Rozwiązanie

Jeden recenzowany katalog generuje eksplorator, case studies i powiązania technologii. Statyczne podstrony działają również bez JavaScript.

Architektura i technologie

  • Recenzowany katalog JSON → walidator → statyczne dokumenty HTML
  • Lekkie interakcje JavaScript bez bibliotek runtime
  • Publiczny artefakt z jawną listą plików

HTML / CSS / JavaScript / Python / GitHub Actions

Potwierdzony zakres

  • Katalog produktów rozdzielony od prezentacji
  • Kategorie, wyszukiwanie i filtry technologii oraz etapu
  • Bezpośrednie adresy projektów i stan filtrów w URL
  • Brief projektu działający lokalnie w przeglądarce

Wyniki i granice weryfikacji

  • Treść projektów jest generowana podczas przygotowania wydania; nie wymaga backendu katalogowego.

Materiały z produktu

Galeria zostanie uzupełniona po przeglądzie materiałów z produktu. Obecna prezentacja opiera się na opisanych źródłach.

Wyzwania i rozwiązania

Wyzwanie
Opisy i statusy projektów były powielane w statycznych sekcjach strony.
Analiza
Audyt V4 wykazał ręczne karty oraz brak indeksowalnych prezentacji większości produktów.
Przyczyna
Treść produktu i warstwa prezentacji nie miały wspólnego modelu.
Decyzja i poprawka
Katalog oddzielono od szablonów i dodano walidację przed generowaniem oraz publikacją.
Weryfikacja
Zakres weryfikacji tej wersji podano w raporcie sprintu; kod generatora i filtry mają osobne testy regresyjne.
Wynik
Aktualizacja jednego rekordu zasila kartę, case study, technologie i listę rozwoju. Wdrożenie pozostaje osobną bramką.
